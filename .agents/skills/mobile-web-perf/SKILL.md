# أداء الويب على الهواتف في «عين»

## القياس قبل التغيير
- لا تعتمد على الإحساس أو المحاكي: قِس زمن الاستدعاءات الحاجبة (`performance.now()` حول `recognizeForVideo` / `detectForVideo` / `detectPose`) وFPS الكشف الفعلي مقابل FPS الرسم على هاتف حقيقي عبر Chrome DevTools (USB).
- وثّق أرقام «قبل/بعد» لكل تحسين في الأداء: FPS الكشف، زمن الكشف بالمللي ثانية، وزمن من وضع اليد حتى النطق.

## ميزانية الإطار
- ميزانية 30 FPS هي **≤ 33ms** لكل شيء على الخيط الرئيسي (كشف + تتبع + رسم + لمس).
- أي كشف يتجاوز هذه الميزانية بانتظام يجب أن ينتقل إلى Web Worker أو GPU delegate، أو يُخفَّض حمل المدخلات (مثل دقة الكشف `480×360` أو تقليل وتيرة `PoseLandmarker`).

## التنعيم والاستجابة
- **طبقة تنعيم واحدة تكفي** (`HandSmoothFilter` / One Euro في `js/smooth.js`).
- كل طبقة EMA إضافية فوقها (`HandTracker.alpha` و`extS`/`anglesS` بنسبة `0.65/0.35`) تضيف تأخيراً ملموساً (~370–400ms عند تبديل شكل اليد حتى مع كاشف 0ms).
- قِس التوازن بين الاستجابة والثبات بالأرقام (زمن انتقال `قبضة ← كف مفتوحة` + نسبة الاهتزاز الكاذب).
